The big picture
Six layers, one direction of trust


Everything the model can do is something Python explicitly allowed. Lower layers never trust higher ones: the model's output is parsed, checked against an allowlist, and only then executed.



  
1 · Interfacepai.py · console script pai
Commands: run, chat, index, search, approvals, approve ID, reject ID, agents, show, revert, create-agent, delete-agent, teach, memory, rules, log. In chat mode the dispatcher picks the agent unless you type @name; the last 6 turns are kept as history. With run you name the agent.

  
2 · Orchestrationrunner.py · agents.py
runner.run() is the think → act → observe loop (max 8 steps). runner.route() chooses an agent, create_agent_for() asks the trainer agent to build one. agents.py loads, validates, backs up and reverts the JSON agent files.

  
3 · Model accessllm.py
The single place the model is called: claude -p --tools "" --setting-sources "" --output-format json --system-prompt …. Built-in tools and your CLAUDE.md are switched off, so the only actions available are the project's skills.

  
4 · Capabilitiesskills.py
22 plain Python functions in one SKILLS dict. Each returns a string. Failures become "error: …" text the model can react to. An agent may call only the skills in its own JSON list.

  
5 · State & knowledgememory.py · index.py · approvals.py
Markdown memory (facts, rules, brand), a SQLite hybrid-search index, and a JSONL approval queue. All plain files you can read and edit.

  
6 · Integrationsmcp.py · connectors/
A stdlib-only MCP client/server pair. Connectors run as subprocesses speaking JSON-RPC over stdin/stdout: a Gmail mailbox server and a read-only SQLite server. External systems: Ollama (embeddings), DuckDuckGo and web pages, Gmail, business.db.

The prompt
Anatomy of the system prompt


Rebuilt from scratch for every run by runner.system_prompt(). The model is told it knows nothing except what is in this prompt, what its skills return, and what the user says.




You are "{agent name}", a small personal assistant
that starts out knowing almost nothing.
You must NOT rely on general world knowledge.
Only trust: 1. MEMORY  2. skill results  3. the user.
If you cannot find it out, say you don't know yet.

YOUR INSTRUCTIONS:      ← agents/NAME.json "instructions"
STANDING RULES:         ← memory/rules.md (every agent)
BRAND GUIDE:            ← memory/brand.md (every agent)
MEMORY:                 ← memory.recall(task)
SKILLS you can call:    ← only this agent's allowlist
  - name: description args={...}


Every reply must be exactly one JSON object:

  use a skill:
  {"thought": "...", "skill": "<name>", "args": {...}}

  when finished:
  {"thought": "...", "answer": "<final answer>"}

Rules baked into the prompt:
  · at most one skill per reply
  · never invent skill results
  · never repeat a call that already failed
  · keep file paths exactly as the user wrote them


Memory recall. With 60 facts or fewer, every fact goes in the prompt. Above that, recall() scores facts by word overlap with the task, keeps the top 50, adds the 10 newest, and says how many were shown.

Retrieval pipeline
How document search finds things




INDEXING · pai index
Files → chunks → vectors
  • Walk sources, skip hidden dirs and .git, venv, node_modules…
  • Extract: PDF, DOCX, PPTX, XLSX (zip + XML, stdlib) and text types
  • Chunk 1,200 chars, 200 overlap, cut at newline or sentence
  • Embed with nomic-embed-text in batches of 32, unit-normalised
  • Unchanged files (same mtime) are skipped; deleted files are dropped


QUERYING · search_docs
Two rankers, one fusion, one judge
  • Lexical: BM25 (k1 1.5, b .75), top 40
  • Semantic: cosine vs every stored vector, top 40
  • Fuse: reciprocal-rank fusion (k 60) → 20 candidates
  • Rerank: model returns the useful passage numbers, best first
  • Fallbacks: Ollama down → BM25 only; rerank error → top-k by fusion





Guardrails
What stops it going wrong




01
Model has no tools
The Claude CLI runs with --tools "" and --setting-sources "". It can only emit text.


02
Per-agent allowlist
Skills not in the agent's JSON are refused before execution.


03
No repeated calls
Identical skill+args pairs are remembered per run and answered with an error.


04
Step budget
8 steps by default (max_steps per agent). On exhaustion the runner returns what it gathered.


05
Approval queue
Skills flagged approval are enqueued. skills.run(gated=True) refuses them even if reached by another path.


06
Read-only database
SQLite URI mode=ro, single SELECT/WITH only (a trailing ; is stripped, any other is rejected). LIMIT 50 is appended only when the query has no trailing LIMIT of its own.


07
Bounded delegation
One level deep, existing worker agents only, never to another planner.


08
Output clipping
Skill results capped at 12,000 chars; stored tool log slices at 2,000 per call.


09
Reversible self-edits
Every agents.update writes a timestamped backup first; revert restores the newest.




Design note. The approval gate lives in the Python runtime (runner + skills.run), not in the email MCP server. The server's own send tool has no gate, and the source says the same servers can be registered with any other MCP client. Treat the gate as protecting this app's agents, not the mailbox itself.





When things go wrong
Failure behaviour




SituationWhat happens


Model replies with non-JSON_parse falls back to treating the raw text as the final answer.


claude missing / non-zero exit / timeoutLLMError; ask retries twice (2 s, 4 s) with a 300 s timeout per call.


Skill raises or gets bad argsCaught in skills.run; returned as error: … into the transcript.


MCP server dies or isn't configuredMCPError becomes error: …. If it exited while a reply was awaited, the client restarts it on next use; a broken pipe on write keeps reporting "not running".


Memory update failsOnly LLMError is caught (answer still returned, run still logged). Other errors such as a file-write OSError would propagate.


Ollama not runningIndex stores chunks without vectors; search uses BM25 only.


Rerank failsFalls back to the top-k fused hits (no retry).


Agent runs out of stepsReturns "I ran out of steps…" plus the first 3,000 chars of the tool log.
