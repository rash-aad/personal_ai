How Personal AI works

A small Python runtime gives a language model a job, a limited set of skills, and memory. The model chooses what to do; Python performs the actual actions and returns the results.

The internet question

How does an agent get online?

The model does not open a browser or make web requests itself. It asks the Python runtime to call a web skill. The skill code is what makes the network request.

1 · Agent decidesBrowser agent emits JSON asking for web_search with a query.
2 · Runner checksRunner confirms the agent is allowed to use that registered skill.
3 · Python fetchesskills.py uses urllib to request DuckDuckGo or a URL.
4 · Text returnsHTML is stripped into text and sent back into the model's next prompt.
5 · Agent answersModel summarizes the returned page text and can cite the URLs it received.
In this project, the browser agent is a tool user, not a browser. web_search fetches DuckDuckGo's HTML results page. fetch_url downloads one specified page. Both use Python's standard-library HTTP client. The HTML is simplified to text; there is no JavaScript browser, cookies/session automation, or general-purpose browsing engine in these skills.
There are two separate network paths: the claude CLI communicates with its model service to generate responses, while the Python web skills contact DuckDuckGo and requested websites. The CLI is launched with built-in tools disabled, so web access comes from the project's Python skills.
A request, end to end

What happens during a run

01 / CONFIGURATION

Pick an agent

Each agents/*.json file defines a name, purpose, allowed skills, and instructions. In interactive chat, a dispatcher chooses one. Or use pai run reader ... to pick directly.

02 / CONTEXT

Build the prompt

The runner combines agent instructions with standing rules, the Praxos brand guide, and relevant memory. It tells the model to return one JSON object per step.

03 / THINK + ACT

One skill per step

The model returns either a final answer or a skill name and arguments. Python runs the function, appends its result to the conversation, and asks the model what to do next. Repeated calls are blocked; the agent has a step limit.

04 / REMEMBER

Log and learn

After a run, another model call can extract facts and standing preferences into memory/. A JSONL run record is written under logs/. You can inspect or edit these files.

05 / CONNECTORS + GUARDRAILS

Local skills, separate permissions

Business database and email operations use small MCP servers started as subprocesses and spoken to over standard input/output. Database connections use SQLite read-only mode and only allow SELECT/CTE queries. Email sending is marked as approval-required: the call enters a queue, and only pai approve ID actually sends it.

A mental model

Who does what?

The model chooses

It reads the task and context, then proposes a skill call or final response. It does not directly execute Python functions.

The runtime enforces

It checks the skill is on that agent's allowlist, runs it, blocks duplicate calls, manages approvals, and puts results back into the prompt.

Skills do the work

Skills are ordinary Python functions in personal_ai/skills.py: read a file, fetch a URL, search an index, query a connector, or write a file.

Files hold state

Agent definitions, memory, brand voice, sources, approvals, and logs are stored in project files. The search index and business database are SQLite files.
